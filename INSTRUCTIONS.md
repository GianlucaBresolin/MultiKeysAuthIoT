# Instructions

## Prerequisites

Before running the project, install the following tools:

- Docker Engine or Docker Desktop
- Docker Compose, available in recent Docker installations as `docker compose`
- OpenSSL
- Bash (required to run `run_experiment.sh`, including on Windows through WSL,
  Git Bash, or another B ash-compatible environment)

For Docker installation instructions, see the official documentation:
[https://docs.docker.com/get-docker/](https://docs.docker.com/get-docker/)

Make sure Docker is running before continuing.

## Configuration and keys

The project uses the following values:

- `KEYS`: the initial keys loaded by the IoT device;
- `SERVER_KEYS`: the same key set loaded by the server;
- `SKEY`: the device secret key;
- `KEY_COUNT`: the number of generated keys;
- `P`: the number of keys selected for an authentication challenge.

These values are read from the `.env` file in the project root. The file is
generated by `run_experiment.sh` and is ignored by Git because it contains
secret material. 

If the repository was obtained from a copy that already includes a root `.env`
file, Docker Compose uses those values automatically. In a fresh clone, `.env`
may not be present: in that case, run `run_experiment.sh` to generate it before
starting the services. 

## Setup and execution

From the folder containing `docker-compose.yaml`, to enable cross-platform CPU
architecture emulation, run the following command 
```bash
docker run --privileged --rm tonistiigi/binfmt --install all 
```

Run the experiment script from the project root in a Bash-compatible terminal:

```bash
chmod +x run_experiment.sh
./run_experiment.sh
```

On Windows, Bash can be provided by WSL, Git Bash, or another Bash-compatible
environment. 

The script:

1. asks how many keys should be generated;
2. generates that number of random 32-byte keys with OpenSSL;
3. generates the device secret key (`SKEY`);
4. writes `KEYS`, `SERVER_KEYS`, `SKEY`, and `KEY_COUNT` to `.env`;
5. starts the Docker Compose build.

The script generates the configuration and starts the Docker Compose build. If
you prefer to generate the `.env` first and start the services separately, run
the script and then use: 

```bash
docker compose up --build
```

## Running scenario

When the stack starts, Docker Compose:

1. generates a short-lived self-signed TLS certificate for Vault;
2. starts HashiCorp Vault;
3. initializes Vault and creates the device policy and service token;
4. builds and starts the Elixir CoAP server;
5. builds the Rust IoT device and starts it in QEMU;
6. establishes the authentication session and sends encrypted telemetry data.

The server listens for CoAP traffic on UDP port `5683`. Logs from the server and
the emulated device can be inspected with:

```bash
docker compose logs -f server iot_device
```

To stop the scenario, press `Ctrl+C`. To stop and remove the containers, use:

```bash
docker compose down
```
